검토 메모

  • 레이아웃: 사용자 상세·초대는 전역 메뉴가 아니라 사용자 목록에서 진입한다. — 목록 화면의 행 클릭·초대 버튼 확인
  • 레이아웃: 모바일에서는 결제 메뉴가 숨겨지고 결제 수단 화면도 노출되지 않는다. — 모바일 내비게이션 확인
  • 권한: 프로젝트 설정은 owner에게만 노출된다. — owner/admin/member 역할별 확인
  • API: API only 2건은 화면 구조도에 넣지 않고 별도 시트에 분리했다. — API only 시트 확인
  • 상태: 리포트 화면은 planned 상태이며 실제 캡처가 없다. — 기획 확정 후 재수집
  • 증적: 스크린샷은 엑셀에 삽입하지 않고 screens/ 아래 파일 경로만 기록한다. — 실제 수집 시 PNG 파일 저장
  • 수집 방식: Playwright는 선택 사항으로 두고, 권한·소요 시간 때문에 에이전트가 실제 화면을 먼저 확인한다. — 자동 수집이 필요한 경우 별도 옵션
  • 구조: Depth 컬럼은 실제 메뉴 계층만 표시하고, 상세·탭·액션 화면은 부모 화면으로 연결한다. — 사이트 구조 시트 확인
  • Depth: 1~2Depth는 항상 유지하고, 실제 메뉴가 더 깊으면 프론트 소스·레이아웃 분석으로 컬럼을 추가한다. — 실제 수집 후 Depth 컬럼 수 확인
  • KRDS: 메인 메뉴는 서비스 정보 구조를 반영하고 최대 3수준까지 사용한다. 현재 샘플은 2수준이다. — 3Depth 메뉴가 필요하면 컬럼 추가
  • KRDS: 현재 페이지는 활성 메뉴로 명확히 표시하고, 모바일은 별도 메뉴 패턴을 확인한다. — 활성 메뉴·모바일 메뉴 확인
  • 접근성: KWCAG 2.2 기준 키보드 탐색·계층 구조·aria-current를 확인한다. — 메뉴 접근성 확인
  • 품질관리: 전자정부 웹사이트 품질관리 지침의 품질 기준을 확인한다. — KRDS·품질관리 지침

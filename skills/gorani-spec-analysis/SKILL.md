# 기획서 분석

기획서 원본을 보존한 채 markdown으로 변환하고, 용어·도메인·프로세스·플로우차트·검증 결과를 하나의 문서 패키지로 정리합니다. 원문에 없는 업무 규칙을 만들지 않고, 사실·추론·질문을 분리합니다.

## 전제

- 입력 파일 경로와 출력 디렉터리를 확인합니다. 파일이 여러 개면 주 기획서와 참고 문서를 구분합니다.
- 변환 도구는 로컬에서 실행합니다. 고객 기획서를 외부 OCR·번역·LLM 서비스로 업로드하지 않습니다. 사용자가 명시적으로 승인한 경우에만 외부 도구를 씁니다.
- PDF·DOCX·PPTX·HWP·XLSX를 모두 같은 품질로 변환할 수 있는 단일 도구는 없습니다. 파일 형식에 맞는 도구를 고르고, 변환 손실을 기록합니다.
- 원본 파일은 절대 덮어쓰지 않습니다. 변환 결과와 분석 문서는 별도 디렉터리에 씁니다.
- 변환 원문을 산출물에 남길지 먼저 묻습니다. 선택지는 `both`(기본), `plain`, `trace`, `none`입니다. 답이 없으면 `both`로 두고 `index.md`에 가정을 기록합니다.
- ID·링크 작업 수준을 함께 묻습니다. 선택지는 `full`(기본), `ids`, `none`입니다. `full`은 의미 기반 ID·문서 지도·Index·상호 링크·링크 검사를 수행하므로 시간이 더 걸립니다.
- 기획서에 없는 내용은 추측해서 채우지 않습니다. 필요한 결정은 질문으로 남깁니다.
- 결과물은 기본적으로 내부 문서입니다. 사용자 지시 없이 커밋·푸시하지 않습니다.

실행 전에 두 가지를 확인합니다.

1. 변환 원문 보존: `both` / `plain` / `trace` / `none`
2. ID·링크 작업 수준: `full` / `ids` / `none`

## 절차

1. 입력을 확인합니다. 파일 형식, 페이지·슬라이드·시트 수, 언어, 문서 버전, 작성자, 관련 문서를 기록합니다.
2. 작업 디렉터리와 임시 변환 디렉터리를 만듭니다. 기본 위치는 `docs/spec/<slug>/`이고, 원본은 그대로 둡니다. 이 단계에서 원문 보존 선택(`both`/`plain`/`trace`/`none`)과 ID·링크 작업 수준(`full`/`ids`/`none`)을 확인합니다.
3. 형식에 맞는 도구로 임시 디렉터리에 `source.plain.md`와 `source.md`를 만듭니다. 원문의 제목·문단·목록·표를 그대로 옮기고, 선택한 파일만 작업 디렉터리로 복사합니다. `none`이면 복사하지 않습니다.
4. 두 원문의 변환 충실도를 확인합니다. 페이지·슬라이드 수, 제목, 표, 이미지, 각주, 빈 페이지가 원본과 맞는지 대조합니다. 누락이 있으면 `warnings`에 적고 사용자에게 알립니다.
5. 문서 구조를 파악합니다. 장·절·페이지·슬라이드 단위로 섹션 맵을 만들고, 요구사항·정책·데이터·화면·일정이 어디에 있는지 표시합니다.
6. 용어를 추출합니다. 업무 용어, 액터, 상태, 이벤트, 규칙, 외부 시스템, 약어를 후보로 모으고 정의·동의어·충돌을 정리합니다.
7. 도메인을 모델링합니다. 엔티티, 값 객체, 관계, 상태 전이, 불변식, 소유자를 정리하고 Mermaid 클래스 다이어그램으로 표현합니다.
8. 프로세스를 정의합니다. 액터, 트리거, 사전 조건, 단계, 결정, 예외, 사후 조건, 입출력을 표로 정리합니다. AS-IS와 TO-BE가 있으면 분리합니다.
9. 플로우차트를 그립니다. 프로세스마다 Mermaid `flowchart`를 만들고 정상·대안·예외 경로를 포함합니다. 각 노드는 프로세스 단계와 대응시킵니다.
10. 검증합니다. 용어·도메인·프로세스·요구사항·일관성·추적성을 점검하고 심각도별 finding을 만듭니다.
11. 인덱스를 작성합니다. 문서 범위, 핵심 요약, 원문 보존 선택, ID·링크 작업 수준, 산출물 목록, 결정 필요 항목, 준비 상태를 한 페이지에 정리합니다.
12. 사용자에게 unresolved 항목을 질문합니다. 답이 오면 문서를 갱신하고, 답이 없으면 `질문` 상태로 남깁니다.
13. 원문 보존이 `none`이면 임시 변환 디렉터리를 삭제하고, `index.md`에 `원문 보존: none`과 삭제 확인을 적습니다.

## 문서 변환

| 입력 | 우선 도구 | 대체 | 확인 |
| --- | --- | --- | --- |
| Markdown | 직접 읽기 | - | 원문 보존 |
| TXT | 직접 읽기 | - | 인코딩 확인 |
| PDF | `pdftotext -layout` | `markitdown`, `pymupdf` | 페이지 수, 표, 스캔 여부 |
| DOCX | `pandoc` | `markitdown` | 제목, 표, 이미지, 각주 |
| PPTX | `markitdown` | `python-pptx` | 슬라이드 수, 제목, 표, 노트 |
| XLSX | `markitdown` | `openpyxl`, `pandas` | 시트명, 병합 셀, 수식 |
| HWP | `hwp5txt` | LibreOffice로 DOCX 변환 후 `pandoc` | 표, 이미지, 각주 |
| 스캔 PDF·이미지 | OCR 도구 | `read` 도구의 PDF 지원 | 텍스트 인식률, 누락 페이지 |

- 도구가 없으면 아래 `## 도구 설치` 원칙에 따라 자동 설치를 시도합니다. 설치를 거부하거나 실패하면 대체 도구를 쓰거나 사용자가 markdown·텍스트를 제공하도록 요청합니다.
- PDF를 `read` 도구로 읽을 수 있으면 페이지별 텍스트를 확인하는 보조 수단으로 씁니다. 도구 지원 여부는 환경마다 다릅니다.
- `source.plain.md`는 원문을 읽기 위한 단순 변환입니다. YAML frontmatter, 표 번호, 레이아웃 주석, 분석 문구를 넣지 않습니다.
- `source.md`는 추적용 변환입니다. `source.plain.md`와 같은 본문에 페이지·슬라이드 표시, 표 번호, 이미지·레이아웃 메모, 변환 warnings를 더합니다.
- 표는 markdown 표로 옮기고, 병합 셀처럼 표현이 깨지는 부분은 원본 페이지를 병기합니다.
- 이미지는 본문에 넣지 않되, 이미지 번호·캡션·원본 페이지를 기록하고 `warnings`에 남깁니다.
- 페이지·슬라이드 표시는 `[p.12]`, `[slide 7]`, `[sheet:예약]`처럼 붙여 추적성을 유지합니다.
- `source.md` 상단에 `source`, `format`, `pages`/`slides`, `converter`, `converted_at`, `warnings`를 기록합니다.
- 변환된 markdown은 원문을 요약하지 않습니다. 분석은 별도 문서에서 합니다.
- 입력이 Markdown이면 `source.plain.md`는 frontmatter를 제거한 본문으로 둡니다.

## 원문 보존 선택

변환을 시작하기 전에 원문 변환 파일을 산출물에 남길지 묻습니다.

| 선택 | 산출물 | 동작 |
| --- | --- | --- |
| both | `source.plain.md` + `source.md` | 기본. 단순 변환과 추적용 변환을 모두 남김 |
| plain | `source.plain.md` | 단순 변환만 남김 |
| trace | `source.md` | 추적용 변환만 남김 |
| none | 없음 | 임시 변환본으로 분석한 뒤 삭제. 분석 문서만 남김 |

- 답이 없으면 `both`를 기본값으로 쓰고 `index.md`에 “원문 보존: both (기본값)”이라고 적습니다.
- `none`이어도 분석은 임시 변환본으로 수행합니다. 원문 위치는 `[slide N]`처럼 인용하되, `source.md`/`source.plain.md` 링크는 만들지 않습니다.
- `index.md`에 `원문 보존: both|plain|trace|none`을 기록하고, 실제 존재하는 파일만 문서 지도와 산출물 목록에 넣습니다.
- `plain`이면 `source.md` 링크를, `trace`이면 `source.plain.md` 링크를 만들지 않습니다.
- `none`이면 임시 변환 디렉터리를 분석 종료 후 삭제하고, 삭제 여부를 검증에 적습니다.
- 사용자가 나중에 원문 보존을 요청하면 원본에서 다시 변환합니다. 임시 파일을 무기한 남기지 않습니다.
- 원문에 민감정보가 있으면 기본값을 `both`로 두지 말고 사용자에게 다시 확인합니다.

## ID·링크 작업 수준

의미 기반 ID와 문서 간 링크는 시간이 걸리므로 실행 전에 수준을 확인합니다.

| 수준 | ID | 문서 지도·Index | 상호 링크 | 링크 검사 | 비고 |
| --- | --- | --- | --- | --- | --- |
| full | `V/P/F-{AREA}-{TOPIC}-{NN}` | O | O | O | 기본. 추적성과 검색이 좋아짐 |
| ids | `V/P/F-{AREA}-{TOPIC}-{NN}` | X | X | X | ID 규칙 표만. 링크 작업 생략 |
| none | `V-01`, `P-01`, `F-01` | X | X | X | 가장 빠름. 순차 ID와 기본 문서만 |

- 답이 없으면 `full`을 기본값으로 쓰고 `index.md`에 “ID·링크 수준: full (기본값)”이라고 적습니다.
- `full`에서만 문서 상단 지도, Finding/Process/Flow Index, 상호 링크, 명시 앵커, `check_links.py` 검사를 수행합니다.
- `ids`는 의미 기반 ID와 ID 규칙 표만 만들고, 문서 지도·Index·상호 링크·링크 검사는 생략합니다.
- `none`은 `V-01`, `P-01`, `F-01`, `P01_START` 같은 순차 ID를 문서 순서로 쓰고, ID 규칙 표·문서 지도·Index·상호 링크·링크 검사를 생략합니다.
- `ids`/`none`에서도 원문 위치 `[slide N]`과 finding 근거는 유지합니다.
- `index.md`에 `ID·링크 수준: full|ids|none`을 기록합니다.
- `full`은 링크 검사 결과를 `validation.md`에 적습니다. `ids`/`none`은 링크 검사를 수행하지 않았다고 적습니다.
- 나중에 `none`/`ids`에서 `full`로 바꾸면 ID를 다시 부여하고 링크를 새로 만들어야 합니다. 기존 ID를 재사용하지 않습니다.
- 사용자가 빠른 결과를 원하면 `none`을, ID만 필요하면 `ids`를, 검색·추적까지 필요하면 `full`을 권장합니다.

## 용어 사전

업무적으로 의미가 있거나, 여러 뜻으로 쓰이거나, 액터·상태·규칙을 가리키는 말을 우선합니다. 모든 명사를 기계적으로 넣지 않습니다.

| 용어 | 정의 | 동의어·약어 | 출처 | 상태 | 비고 |
| --- | --- | --- | --- | --- | --- |

- `정의`는 원문을 바탕으로 씁니다. 원문에 정의가 없으면 "정의 없음"으로 둡니다.
- `상태`는 확정·모호·충돌·미정의 중 하나입니다.
- 같은 대상을 다른 말로 부르면 동의어로 묶고, 다른 대상을 같은 말로 부르면 충돌로 표시합니다.
- 영문·한글 표기가 다르면 둘 다 적고, 화면·API·DB에서 쓰는 이름이 다르면 별도로 표시합니다.
- 용어가 처음 나온 위치와 정의가 있는 위치를 구분합니다.

## 도메인 모델

| 구성요소 | 이름 | 속성·책임 | 관계·불변식 | 출처 | 확실성 |
| --- | --- | --- | --- | --- | --- |

- 엔티티, 값 객체, 애그리거트, 도메인 서비스, 외부 시스템을 구분합니다.
- 관계는 1:1, 1:N, N:M과 선택·필수 여부를 적습니다.
- 상태가 있으면 상태 전이와 전이 조건을 적습니다.
- 원문에 없는 엔티티·관계는 `추론`으로 표시하고, 구현 전에 확인할 질문을 남깁니다.
- Mermaid 클래스 다이어그램을 `domain.md`에 넣습니다. 확정 관계는 실선, 추론 관계는 점선으로 표시합니다.
- 용어 사전의 이름과 도메인 모델의 이름이 다르면 매핑을 적습니다.

## 프로세스 정의

프로세스마다 아래 항목을 표로 정리합니다.

| 항목 | 내용 |
| --- | --- |
| 프로세스 ID | P-RESERVATION-CREATE-01 |
| 이름 | 예약 생성 |
| 구분 | AS-IS / TO-BE |
| 액터 | 고객, 운영자, 시스템 |
| 트리거 | 사용자가 예약 버튼을 누름 |
| 사전 조건 | 로그인, 재고 있음 |
| 입력 | 날짜, 장비, 연락처 |
| 단계 | 1. 재고 확인 2. 결제 3. 예약 확정 |
| 결정 | 재고 없음, 결제 실패 |
| 예외 | 중복 예약, 결제 취소 |
| 사후 조건 | 예약 레코드 생성, 알림 발송 |
| 관련 용어 | 예약, 재고, 결제 |
| 출처 | `[p.4]` |

- 액터가 누구인지, 무엇이 프로세스를 시작하는지, 끝났는지 판단하는 조건을 반드시 적습니다.
- 예외·취소·재시도·권한 없음 경로를 빠뜨리지 않습니다.
- AS-IS와 TO-BE를 한 표에 섞지 않습니다.
- 프로세스가 여러 부서에 걸치면 부서별 책임과 인계 지점을 적습니다.
- 예시의 `RESERVATION`은 프로젝트별 AREA입니다. 기본 카탈로그에 없으면 `index.md`에 정의한 뒤 사용합니다.

## 플로우차트

- 프로세스마다 Mermaid `flowchart TD`를 만듭니다.
- 시작·종료, 액션, 결정, 예외를 구분합니다. 결정 노드에는 조건을 씁니다.
- 정상 경로뿐 아니라 실패·취소·권한 없음·재시도 경로를 포함합니다.
- 각 노드 ID는 프로세스 단계와 대응되게 붙입니다. 예: `CREATE01_START`, `CREATE01_CHECK_STOCK`, `CREATE01_NO_STOCK`. `START`와 `END`는 예약어입니다.
- 고객·운영자·시스템이 다르게 행동하면 subgraph로 분리합니다.
- 원문에 없는 분기는 만들지 않습니다. 추론한 분기는 도표 아래에 `추론`으로 표시합니다.
- `mmdc`가 있으면 SVG·PNG로 렌더링합니다. 없으면 아래 `## 도구 설치` 원칙에 따라 설치를 시도하고, 실패하면 Mermaid 소스를 `flows.md`에 둡니다.
- 다이어그램 문법이 깨지면 노드를 단순화하고, 렌더링 가능한지 확인합니다.

## ID 규칙

이 규칙은 ID·링크 수준 `full`과 `ids`에서 사용합니다. `none`은 `V-01`, `P-01`, `F-01` 같은 순차 ID를 씁니다. ID 접두사만 보고 내용 영역을 유추할 수 있어야 하며, 번호는 심각도나 발견 순서가 아니라 **영역별 순번**으로 붙입니다.

형식:

- 검증 finding: `V-{AREA}-{TOPIC}-{NN}`. 예: `V-STATUS-END-01`
- 프로세스: `P-{AREA}-{TOPIC}-{NN}`. 예: `P-LICENSE-ACTIVATE-01`
- 플로우: `F-{AREA}-{TOPIC}-{NN}`. 예: `F-LICENSE-ACTIVATE-01`. 하나의 플로우가 여러 프로세스를 다루면 대표 프로세스 ID를 쓰고 제목에 나머지를 적습니다.
- 플로우 노드: `{TOPIC}{NN}_{NODE}`. 예: `ACTIVATE01_START`, `ACTIVATE01_VALIDATE`. `START`·`END`는 예약어입니다. 같은 TOPIC이 여러 AREA에 있으면 `{AREA}_{TOPIC}{NN}_{NODE}`를 씁니다.
- 화면: 원문 화면 ID를 그대로 씁니다. 분석용 화면 목록이 필요하면 `S-{AREA}-{TOPIC}-{NN}`을 쓰고 원문 ID를 괄호에 병기합니다.

AREA 코드:

| 코드 | 의미 | 포함 |
| --- | --- | --- |
| AUTH | 인증 | 로그인, 비밀번호, 2차 인증, 세션, 계정 잠금 |
| PERM | 권한 | 역할, 권한, 데이터 범위, 접근 제어 |
| ACCOUNT | 계정 | 계정 생성·정지·해제, 직원 계정 |
| ORG | 조직 | 병원·기관·테넌트, 조직 관리 |
| DOMAIN | 도메인 | 핵심 엔티티, 등록·조회·수정·삭제, 업무 규칙 |
| LICENSE | 라이선스 | 라이선스·OTP 발급·활성화·재발급 |
| STATUS | 상태 | 상태 값, 전이, 종료, 취소, 만료 |
| PROC | 프로세스 | 트리거, 단계, 예외, 사후 조건 |
| UI | 화면 | 화면 ID, 필드, 라벨, 검색, 페이지네이션, 네비게이션 |
| DATA | 데이터 | 데이터 모델, 저장, 다운로드, 보존, 이관 |
| REPORT | 리포트 | 대시보드, 집계, 지표, 진행률 |
| INT | 연동 | 외부 API, CDMS, 이메일·SMS, 배치 |
| SEC | 보안 | 개인정보, 감사, 전자서명, 규제 |
| NFR | 비기능 | 성능, 가용성, 확장성, 접근성, 호환성 |
| OPS | 운영 | 배포, 모니터링, CS, 장애 대응, 운영 연락처 |
| DOC | 문서 | 구조, 버전, 승인, 표기, 추적성 |
| TERM | 용어 | 정의, 동의어, 충돌 |

번호와 표기 규칙:

- `TOPIC`은 내용을 유추할 수 있는 영문 대문자 1~3단어를 하이픈으로 연결합니다. 예: `LOGIN`, `END`, `DOWNLOAD`, `RANDOM-ID`.
- `NN`은 두 자리, 같은 TYPE·AREA·TOPIC 안에서 `01`부터 증가합니다.
- 심각도가 바뀌어도 ID를 다시 붙이지 않습니다. 심각도는 별도 컬럼입니다.
- 같은 항목은 `glossary`, `domain`, `processes`, `flows`, `validation`에서 같은 ID를 씁니다.
- 여러 영역에 걸치면 결정권자나 책임 영역을 기준으로 하나를 고르고, 본문에 보조 영역을 적습니다.
- `MISC`, `ETC`, `OTHER` 같은 모호한 코드를 쓰지 않습니다.
- 프로세스와 플로우가 1:1이면 같은 AREA·TOPIC·NN을 씁니다. 1:1이 아니면 플로우 제목에 대응 프로세스 ID를 모두 적습니다.
- 새 AREA나 TOPIC이 필요하면 `index.md`의 ID 규칙 표에 코드와 정의를 먼저 추가합니다. 프로젝트마다 즉석에서 코드를 만들지 않습니다.
- `index.md`에 실제 사용한 AREA 코드와 개수를 적고, TOPIC은 ID Index의 ID와 요약으로 확인할 수 있게 합니다.

## 문서 간 링크

이 작업은 ID·링크 수준 `full`에서만 수행합니다. `ids`/`none`은 문서 지도·Index·상호 링크를 만들지 않습니다. `full`에서는 독자가 `index.md`에서 시작해 finding, 프로세스, 플로우, 용어, 도메인으로 바로 이동할 수 있어야 합니다.

- 모든 문서 상단에 문서 지도를 둡니다. 예: `> 문서 지도: [index](index.md) · [glossary](glossary.md) · ...`
- `index.md`에 문서 지도, Finding Index, Process Index, Flow Index를 둡니다.
- `glossary.md`의 주요 용어는 관련 `domain.md`, `processes.md`, `validation.md` 섹션으로 링크합니다.
- `domain.md`의 엔티티·상태 전이 행은 관련 프로세스와 finding으로 링크합니다.
- `processes.md`의 각 프로세스는 대응 플로우와 finding으로 링크합니다.
- `flows.md`의 각 플로우는 대응 프로세스와 finding으로 링크합니다.
- `validation.md`의 각 finding은 관련 프로세스, 플로우, 도메인 섹션으로 링크합니다.
- 원문을 읽을 때는 `source.plain.md`, 위치를 추적할 때는 `source.md`로 링크합니다. 보존하지 않은 파일에는 링크하지 않습니다.
- `source.plain.md`와 `source.md`는 슬라이드 앵커에 의존하지 않고 파일 링크만 겁니다.

링크 규칙:

- 상대 경로만 씁니다. `docs/spec/<slug>/` 기준으로 `[validation](validation.md#v-status-end-01)`처럼 씁니다.
- 절대 경로, `file://`, 외부 URL을 넣지 않습니다.
- 파일만 링크하지 말고 가능한 한 섹션 앵커까지 겁니다.
- 프로세스·플로우·finding 앵커는 ID를 소문자로 바꿔 붙입니다. 예: `<a id="p-license-activate-01" name="p-license-activate-01"></a>`, `<a id="f-license-activate-01" name="f-license-activate-01"></a>`, `<a id="v-license-channel-01" name="v-license-channel-01"></a>`.
- `index.md`의 ID Index는 ID, 심각도·이름, 한 줄 요약, 문서 앵커를 포함합니다.
- 링크 텍스트는 `여기`, `링크` 대신 대상 ID나 이름을 씁니다.
- 문서 이름이나 앵커가 바뀌면 같은 변경에서 모든 링크를 갱신합니다.

완료 전에 링크를 검사합니다.

- 모든 상대 링크의 파일과 앵커가 존재하는지 확인합니다. 스킬 폴더의 `scripts/check_links.py`를 실행합니다. 예: `python3 <스킬 폴더>/scripts/check_links.py docs/spec/<slug>`.
- 깨진 링크가 하나라도 있으면 완료로 보고하지 않습니다.
- 검사 결과(링크 수, 깨진 링크 0건)를 `validation.md`의 검증 방법에 적습니다.
- Mermaid 안의 `click` 링크는 렌더러 지원이 다르므로 쓰지 않고, 도표 아래 텍스트 링크로 대신합니다.

## 검증

검증은 아래 영역을 모두 봅니다.

| 영역 | 확인할 것 |
| --- | --- |
| 용어 | 미정의, 동의어 혼용, 같은 말의 다른 뜻, 화면·API·DB 이름 불일치 |
| 도메인 | 누락 엔티티, 고아 관계, 잘못된 카디널리티, 상태 전이 누락, 불변식 부재 |
| 프로세스 | 액터·트리거·사후 조건 누락, 예외 경로 없음, 결정 조건 없음, 끊긴 흐름 |
| 요구사항 | 목표·범위·제약·비기능·권한·데이터 보존·연동 실패·마이그레이션·출시 계획 |
| 일관성 | 숫자·날짜·용어·정책 충돌, AS-IS/TO-BE 혼합, 문서 간 상충 |
| 추적성 | 용어·프로세스·플로우 노드가 원문 위치와 연결되는가 |

Finding 형식:

| ID | 심각도 | 영역 | 발견 내용 | 근거·출처 | 권장 조치 | 담당 | 상태 |
| --- | --- | --- | --- | --- | --- | --- | --- |

심각도:

- blocker: 구현·의사결정을 진행할 수 없음
- major: 범위·흐름·데이터·권한이 달라질 수 있음
- minor: 표현·구조·일관성 문제
- question: 제품·운영 결정이 필요함

검증 원칙:

- 모든 finding에는 원문 위치나 문서 근거를 붙입니다.
- 확인하지 못한 것은 "질문"으로 남기고, 추측으로 채우지 않습니다.
- AS-IS와 TO-BE가 충돌하면 어느 쪽이 최신인지 임의로 정하지 않습니다.
- 요구사항과 화면·데이터가 서로 맞지 않으면 양쪽을 함께 인용합니다.
- blocker와 major를 먼저 정리하고, minor는 묶어서 정리합니다.

## 출력 형식

`docs/spec/<slug>/` 아래에 다음 파일을 만듭니다. 원문 보존 선택에 따라 `source.plain.md`·`source.md`는 생성하지 않을 수 있습니다.

| 파일 | 내용 |
| --- | --- |
| `source.plain.md` | 단순 변환 원문. 보존 선택 `both`/`plain`일 때만 생성 |
| `source.md` | 추적용 변환 원문. 보존 선택 `both`/`trace`일 때만 생성. 페이지·슬라이드 표시, 표 번호, 변환 도구, warnings |
| `index.md` | 범위, 한 줄 요약, 원문 보존 선택, ID·링크 수준, 산출물 목록, (full이면) 문서 지도·Finding/Process/Flow Index·AREA 코드와 개수, blocker·major·질문, 준비 상태 |
| `glossary.md` | 용어 사전 |
| `domain.md` | 도메인 모델 표와 Mermaid 클래스 다이어그램 |
| `processes.md` | 프로세스 정의 표, 대응 플로우·finding 링크 |
| `flows.md` | 프로세스별 Mermaid 플로우차트, 대응 프로세스·finding 링크 |
| `validation.md` | 검증 요약, finding 표, 관련 문서 링크, 추적성, 링크 검사 결과, 미해결 질문 |

`index.md`의 준비 상태:

- ready: blocker가 없고 major가 정리됨
- conditional: major 또는 question이 남아 있지만 구현 착수 가능
- blocked: blocker가 있음

모든 문서는 한국어로 쓰되, 원문 용어와 영문 식별자는 보존합니다.

## 실패 처리

- 변환 도구가 없으면 아래 `## 도구 설치` 원칙에 따라 자동 설치를 시도합니다. 설치를 거부하거나 실패하면 대체 도구를 쓰거나 markdown·텍스트를 받습니다.
- 스캔 PDF의 OCR이 안 되면 텍스트를 추측하지 말고, OCR 도구나 원문 텍스트를 요청합니다.
- 표·이미지·각주가 손실되면 `warnings`에 적고, 해당 페이지를 원본에서 확인합니다.
- 문서가 너무 크면 장·절 단위로 나눠 분석하고, 섹션 맵으로 연결합니다.
- 문서 간 내용이 충돌하면 하나를 임의로 선택하지 않고 충돌 표에 함께 적습니다.
- 프로세스가 원문에 없으면 만들지 말고, "프로세스 미정의"로 검증에 올립니다.
- Mermaid 렌더링이 실패하면 노드를 줄이고 문법을 단순화합니다. 렌더링하지 못했으면 그 사실을 적습니다.
- ID가 중복되거나 AREA 없이 붙으면 완료로 보고하지 않습니다. 같은 TYPE과 AREA 안에서 번호를 다시 매기고 `index.md`의 ID 규칙 표를 갱신합니다.
- 상대 링크나 앵커가 깨지면 완료로 보고하지 않습니다. 파일·앵커를 고친 뒤 링크 검사를 다시 실행합니다.
- `source.plain.md` 변환이 실패하면 빈 파일을 만들지 말고, `source.md`의 warnings에 실패 사실을 적고 원문 텍스트를 요청합니다.
- `none` 선택 후 임시 변환본 삭제에 실패하면 완료로 보고하지 않고, 남은 파일 경로를 알립니다.
- `full`에서 링크가 깨지면 완료로 보고하지 않습니다. `ids`/`none`에서는 링크 검사를 수행하지 않았음을 `validation.md`에 적습니다.
- 카탈로그에 없는 AREA가 필요하면 `index.md`에 코드와 정의를 먼저 추가합니다. 정의 없는 코드를 즉석에서 쓰지 않습니다.
- 원본 페이지 수와 변환 페이지 수가 다르면 완료로 보고하지 않습니다.

## 도구 설치

필요한 프로그램이 없으면 자동 설치를 시도합니다.

- OS 패키지 관리자(macOS `brew`, Debian/Ubuntu `apt-get`, Fedora `dnf`, Arch `pacman`, Windows `winget`·`choco`·`scoop`)와 언어 패키지 관리자(`uv`·`pipx`·`npm`·`cargo`·`go`)를 우선합니다.
- 작업에 필요한 도구만 설치합니다. 무관한 패키지나 전체 도구 묶음을 설치하지 않습니다.
- 설치 전에 도구와 명령을 알립니다. 사용자가 설치를 거부하면 설치하지 않고 대체 도구나 입력 파일을 요청합니다.
- 사용자 권한 설치를 우선합니다. `sudo`가 필요하면 `sudo -n`으로만 시도하고 암호 입력을 요구하지 않습니다. 실패하면 실행할 명령과 이유를 보고합니다.
- 공식 패키지·저장소만 사용합니다. `curl | sh`, 출처 불명 바이너리, 임의 URL 다운로드·실행을 금지합니다.
- 설치 후 `command -v`와 `--version`으로 확인합니다. 실패하면 대체 도구를 쓰거나 입력 파일을 요청합니다.
- 설치한 도구·버전·실패 사유를 결과나 evidence에 기록합니다.
- 문서·고객 데이터를 설치 과정에서 외부로 보내지 않습니다.
- GUI 앱·드라이버·커널·서비스처럼 시스템 변경이 큰 설치는 먼저 확인합니다.

## 금지

- 원문에 없는 업무 규칙·용어·도메인 관계를 사실처럼 쓰지 않습니다.
- 기획서를 외부 OCR·번역·LLM 서비스에 무단 업로드하지 않습니다.
- 원본 파일을 덮어쓰거나 삭제하지 않습니다.
- AS-IS와 TO-BE를 한 표·한 도표에 섞지 않습니다.
- 변환 손실을 숨기고 "변환 완료"로 보고하지 않습니다.
- 검증 finding의 근거 없이 blocker/major를 단정하지 않습니다.
- `MISC`, `ETC`, `OTHER`처럼 내용을 유추할 수 없는 ID를 쓰지 않습니다.
- 절대 경로·`file://`·외부 URL로 문서 간 링크를 만들지 않습니다.
- 사용자가 `none`/`ids`를 선택했는데 의미 ID·문서 지도·상호 링크를 임의로 추가하지 않습니다.
- 사용자가 `full`을 선택했는데 링크 검사를 생략하지 않습니다.
